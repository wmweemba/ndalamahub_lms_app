# Frontend rules

Moved verbatim from CLAUDE.md on 2026-10-21. Loads only when Claude works with matching files. Full prior file: `docs/history/CLAUDE-2026-10-21.md`.

**The design system is live** (adopted 2026-07-16, fully built out as of 2026-07-17): `docs/UI_SPEC.md` is the source of truth for all visual/UX decisions on this app — design system (Part A: three registers, palette, typography, component rules) and build spec (Part B: screen inventory, demo scope, conventions, testing approach). All UI changes must conform to it. The six-phase Manifi demo runway (`docs/12-…` through `docs/17-…`) is complete and merged: tokens, fonts, brand assets, the shared `AppLayout`, login, dashboards, loans workflow, loan forms/repayments/products, the borrower consumer register, and the admin surfaces (Companies/Settings/Reports/Support) are all on the design system. `docs/18-post-demo-ui-punchlist.md` is the only remaining doc — a backlog, not a session; see UI_SPEC §12 for what's deliberately deferred (dark platform-admin register, Settings placeholder tabs, auth screens beyond the login restyle, charts, `window.confirm`→styled dialogs, RHF+Zod adoption). Rules for frontend work going forward:

- Any new UI work (post-demo punch list items, new features) must conform to `docs/UI_SPEC.md` — treat it as living style-guide, not a one-time migration target. If a change would contradict it, stop and flag rather than drift.
- **UI-only changes still make zero server changes** as a matter of habit from the demo runway, though this is no longer a hard phase-doc gate now that the runway is done — `git diff main -- server/` should still come back empty for a change that only touches presentation. A UI change that turns out to need a server change stops and flags it rather than reaching into `server/` unplanned.
- Client gates: `cd client && pnpm lint && pnpm build && pnpm test` (Vitest + React Testing Library, deliberately minimal — see UI_SPEC §14). Server suite (261 tests) stays untouched by UI-only work.
- The dark platform-admin register, the removed Settings placeholder tabs, and charts are deliberately post-demo — see UI_SPEC §12 before "improving" any of them. **Auth screens are no longer in that list**: the forgot-password/reset UI was built 2026-07-29 and all three auth screens were redesigned 2026-07-30 (see below).
- **Auth screens are a documented exception to UI_SPEC §1.5 "flat over decorative"** — gradient, accent halo, layered shadow, floating card and diagonal clips. They are a showcase surface. **Do not carry that treatment inward** to dashboards, tables or dialogs. Styles are isolated in `client/src/index.css` under `@layer components`, all prefixed `auth-`. The left panel is a deliberate swappable slot; see `docs/design/auth-panel-image-brief.md` before changing it.
- **Never write `bg-[--token]` (or `text-`/`border-[--token]`).** This project is on Tailwind **v4.1**, which removed the v3 shorthand that expanded `[--token]` to `var(--token)`. It fails **silently** — no lint error, no build error — emitting invalid CSS (`background-color:--primary`) that browsers drop. Use the `@theme inline` utilities (`bg-primary`, `text-muted-foreground`, `border-input`, `focus:ring-ring`, …). See UI_SPEC §13 for the detection grep. **Swept clean in Phase 28** (`docs/28-tailwind-v4-token-sweep.md`, 2026-07-30) — 38 occurrences across 5 files converted, zero dead rules remain. Treat this as a standing rule, not a closed migration: `pnpm lint` and `pnpm build` both pass while the bug is present, so only the UI_SPEC §13 grep proves it.
