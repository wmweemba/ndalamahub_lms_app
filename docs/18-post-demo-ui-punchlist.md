# Phase 18 — Post-demo UI punch list

**Planned:** 2026-07-16 (Claude Code Fable). **Status: backlog, not a build session.** Nothing here blocks the Manifi demo. After the demo, William prioritizes this list with the planning agent and items get promoted into properly-scoped phase docs (some need server work and therefore cannot be UI-phase items).

This file exists so the deliberate scope cuts made during the demo runway (2026-07-16 planning session, recorded in `docs/UI_SPEC.md` §12) are never silently forgotten.

## Items

1. **Dark platform register** (`platform_admin` control room) — mockup exists (`docs/design/mockups/dashboard-platform-admin-dark.html`), tokens defined (UI_SPEC §3.4), `.dark` CSS block reserved. Scope: dark token values into `index.css`, register switch for platform_admin, dashboard + Billing surfaces first. Client-only.
2. **Settings stub tabs rebuilt for real** — Security, Notifications, Integrations were removed in Phase 12 (they were local-state fakes with dead Save buttons). Rebuilding any of them requires server-side settings storage and routes → needs its own full-stack phase doc; decide first whether they're even wanted (notification prefs may be the only real one — reminder emails exist since Phase 09).
3. ~~**Report export wiring**~~ — **DONE, verified 2026-07-29.** Fully wired end to end: server `GET /reports/:type/export/:format` (`server/routes/reports.js:298`) streams real PDFKit/ExcelJS output with `Content-Disposition: attachment`, behind `requireAuth` + `authorizeMinRole('employer_hr')`; client `ReportModal.jsx:18` fetches with `responseType: 'blob'`, builds an object URL, sets the `download` attribute with the right extension, and toasts on success/failure. This was the last open launch-smoke item. *Minor polish left:* the error branch reads `err.response.data?.message`, but with `responseType: 'blob'` an error body is also a Blob, so that is always `undefined` and the toast falls back to `Server error: <status>`. Harmless (it degrades gracefully); to show real server messages, read the blob back as text in the catch.
4. **`window.confirm` → styled confirm dialogs** (companies delete, products delete). Client-only, small.
5. **RHF + Zod adoption** for the big forms (product dialogs, user dialogs, apply flow) — deps already installed. Client-only, do per-form.
6. **Sonner sweep** — toasts adopted progressively from Phase 12; audit remaining silent `console.error` failure paths.
7. **Charts with real data** — no trend endpoints exist (the old sample chart was removed in Phase 13). Needs server aggregation endpoints → full-stack phase; follow UI_SPEC §6 chart rules when built.
8. **Auth screens** — **forgot-password/reset UI DONE 2026-07-29** (built pre-handover; `ForgotPasswordPage.jsx` + `ResetPasswordPage.jsx`, registered outside `ProtectedRoute`). This also repaired the staff- and customer-invite emails, which pointed at a `/reset-password` route that did not exist and silently redirected to `/login` — any invite sent before that date was unusable. Remaining under this item: token refresh handling, and whatever else the auth migration (CLAUDE.md §8) brings. Post-launch nice-to-haves surfaced while building it: a tighter per-route rate limit on `/auth/forgot-password` (currently only the shared `/api/auth` 50-per-15-min limiter, so ~50 reset emails could be sent to one known address in that window), making the two forgot-password success messages identical to close the enumeration oracle, and test coverage for both auth routes and both new pages.
9. **Accessibility pass** — full audit per UI_SPEC §8 (per-phase spot checks happened; contrast verification for accent-on-white body text, keyboard traversal of dialogs, focus states).
10. **PWA manifest** — audited 2026-07-29; icons in `client/public/brand/raster/` verified correct (192/512/maskable-512/apple-touch-180, maskable art inside the safe zone). Full plan in `docs/PWA_IMPLEMENTATION_PLAN.md`. **Phase A** (static manifest + `<head>` tags, no dependency, no build change) is safe whenever wanted. **Phase B** (service worker) is deliberately blocked — see that doc §4; the binding constraint is that Coolify's Nixpacks static build has no way to set `Cache-Control: no-cache` on `/sw.js`, which makes a bad service worker unrecoverable. Deferred by William until Manifi has been stable in production for a week.
11. **Wordmark outlining** — lockup SVGs use live Inter `<text>`; convert to paths before any standalone/print/social use (see `docs/design/brand-assets-README.md`).
12. **Client dep-audit leftovers** — re-audited 2026-07-29 (NS-002 full). The dev-toolchain findings (`rollup`, `picomatch`, `postcss`, `esbuild`, `ajv`, `brace-expansion`, `js-yaml`, `@babel/core`, `minimatch`, `flatted` via vite/eslint/vitest) are build-and-lint-time only, never in a browser session or on the server — genuine P2 hygiene, safe to batch post-launch. **`form-data` via axios is a false positive:** `form-data@4.0.5` is installed under `client/node_modules`, but axios is not a server dependency, and `axios@1.18.1`'s own `browser` field maps `./lib/platform/node/classes/FormData.js` → `./lib/helpers/null.js`, so it is excluded from the browser bundle. `pnpm audit` walks the dependency graph, not the bundle. No action needed; do not bump axios for security reasons. Post-launch queue: helmet 8.2→8.3, axios 1.18→1.19, the dev-toolchain batch, and `.npmrc` hardening.
13. **`/users` directory view** — removed in Phase 17 as an orphaned duplicate of Settings → User Management; revisit only if a cross-company user directory becomes a real need.
14. **Tenant branding config layer** — UI_SPEC §1.2's "future config layer" (per-lender logo/accent). Only when a second lender client makes it worth designing; must be configuration, not a token fork.
